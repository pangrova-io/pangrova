# TPC-H Reference Files

Standard TPC-H benchmark queries (Q1-Q22) and precomputed expected results for Pangrova E2E correctness testing.

## Directory Structure

```
tpch/
├── queries/       # Standard TPC-H SQL files (Q1-Q22), unqualified table names
│   ├── q01.sql    # Pricing Summary Report
│   ├── q02.sql    # Minimum Cost Supplier
│   ├── ...
│   └── q22.sql    # Global Sales Opportunity
├── expected/      # Precomputed JSON result files
│   ├── q01.json
│   ├── q02.json
│   ├── ...
│   └── q22.json
└── README.md
```

## SQL Files

- Use **unqualified table names** (e.g., `lineitem`, `orders`). The `TpcHCorrectnessTest` handles catalog/schema prefixing at runtime.
- Standard TPC-H table names: `lineitem`, `orders`, `customer`, `supplier`, `nation`, `region`, `part`, `partsupp`.
- SQL syntax targets Calcite-compatible dialect (Pangrova's SQL engine).
- Each file contains exactly one query.

## Expected Result Files

- JSON format: `{"note": "...", "query": "...", "scaleFactor": 0.01, "rows": [...]}`.
- Generated by DuckDB at scale factor 0.01 as reference ground truth.
- For floating-point columns, values are rounded to 4 decimal places.
- Queries with ORDER BY (Q1-Q5, Q7-Q13, Q15-Q16, Q18, Q20-Q22) use ordered comparison.
- Queries without ORDER BY (Q6, Q14, Q17, Q19) use order-independent comparison with tolerance.

## Regenerating Expected Results

Run `python3 generate_expected.py` from this directory. Requires `duckdb` Python package:
```bash
pip install duckdb
python3 generate_expected.py
```

## Usage

`TpcHCorrectnessTest` loads SQL from `queries/qNN.sql`, prefixes table names with the test catalog/schema, executes through the real pipeline, and compares results against `expected/qNN.json`.
