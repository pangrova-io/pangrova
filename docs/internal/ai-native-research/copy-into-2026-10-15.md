# COPY INTO execution boundary, 2026-10-15

## Evidence and semantics

- The grammar accepts `COPY INTO target FROM 'uri'` with file options and
  `COPY INTO target FROM (setQuery)`, but the previous AST builder had no
  `visitCopyIntoStatement`. No URI discovery, file scanner, loaded-file
  identity, or COPY commit path was wired. Four existing E2E cases named a
  nonexistent `s3://test-bucket` location and only checked command success;
  they did not establish that any row was loaded.
- [Snowflake COPY INTO](https://docs.snowflake.com/en/sql-reference/sql/copy-into-table)
  applies its `FROM (SELECT ...)` transformation to staged files. It also
  specifies file format and filtering options for file loads. An arbitrary
  table-to-table query is therefore a Pangrova extension, not claimed
  Snowflake-compatible COPY syntax.
- [Databricks COPY INTO](https://docs.databricks.com/aws/en/ingestion/cloud-object-storage/copy-into/)
  promises retryable, file-level idempotent ingestion: files already loaded
  are skipped. Pangrova's table-to-table SELECT extension has INSERT SELECT
  semantics and appends rows on each execution; it cannot inherit that
  file-ingestion guarantee.
- [Iceberg's specification](https://iceberg.apache.org/spec/) makes an atomic
  metadata pointer swap the commit boundary. A safe future file loader must
  associate selected source-file identities with this commit boundary (or a
  fenced journal), and determine the result after ambiguous commit responses.
- [Databricks' COPY INTO contract](https://docs.databricks.com/gcp/en/sql/language-manual/delta-copy-into)
  skips files already loaded, including modified files at the same path. Its
  [external location model](https://docs.databricks.com/aws/en/data-governance/unity-catalog/securable-objects)
  binds a storage credential to a path and requires a separate file-read
  privilege. These are separate from target-table INSERT authorization.

## Reachable increment

The parser now lowers `COPY INTO target FROM (SELECT ...)`, without file
options, to the existing `InsertSelectStatement`. This reuses its target
authorization, planning, native scan/write, and catalog commit path. URI
sources and file options on a SELECT source fail with the structured
`PARSER_UNSUPPORTED_FEATURE` error before a write. Parser tests exercise the
supported and rejected shapes. The E2E test exercises real source rows,
filtered values, and repeated append behavior; its result must be recorded
only after the integrated SQL/JNI run completes.

## File-loader acceptance still open

The existing `StorageProfile` SPI now parses object URLs and matches the
configured backend, bucket, and complete prefix path segments. It rejects
ambiguous encodings, traversal, query/fragment decorations, and LOCAL URLs;
LOCAL requires canonical filesystem and symlink resolution before it can
authorize a file. This SPI is an authorization prerequisite, not an active
COPY source: `COPY INTO ... FROM 'uri'` still fails closed at parsing, and the
in-memory profile registry has no per-principal grants or durable credentials.

The current `WriteCommitEntry` and `WriteCommitFingerprint` deduplicate one
query's commit replay using its query ID and fragments. They do not record a
source-file identity across separate COPY statements. Adding a scanner alone
would thus duplicate rows on a second run. File identities must be frozen from
the authorized file listing, and their committed state must be published with
the target table's atomic commit or through a fenced, reconcilable journal.
Concurrent COPY writers must recheck identities after commit conflicts, while
ambiguous commit responses must reconcile against the target's committed
state before retrying. An object overwritten at the same URI needs an explicit
product rule: path-only dedup follows Databricks' behavior, while version-aware
dedup permits reloading the new object. Neither rule is implemented yet.

### Smallest complete file path to build

The first complete vertical slice should be one exact `s3://bucket/key.parquet`
object into an Iceberg target. It should require a configured, durable S3
external location, an authenticated file-read grant, target INSERT permission,
and a versioned source object. Directory listing, `PATTERN`, CSV, JSON, OSS,
GCS, ADLS and LOCAL remain rejected in this slice. A single exact object
avoids pretending a directory listing is a stable snapshot. The S3 `versionId`
must be captured by HEAD and used to [read that exact version](https://docs.aws.amazon.com/AmazonS3/latest/userguide/RetrievingObjectVersions.html),
or copied by source version to immutable managed staging before the Native
reader opens it; a path or ETag alone cannot pin the bytes read during a
concurrent overwrite. Pangrova's Velox S3 reader has no verified versioned
read contract yet, so the staging option needs an explicit implementation and
test, not a bare query parameter added to a split URI.

The execution route should keep the one SQL→Calcite→Substrait→JNI→Native
scan→Native write→catalog commit path. A typed URI COPY AST must bind a
query-owned, read-only file relation with Parquet footer schema checked
against the Iceberg target; its connector emits a canonical v2 `DataSplit`
with `FILE_FORMAT_PARQUET`, exact immutable staged object identity, and a
trusted object-store execution binding. `PlanSplitSourceExtractor` and
`SplitFetcher` then see an ordinary bound scan. The current
`NativeReadSplitBinding` covers only Paimon/Lance and must validate this new
connector's tenant and location; it must never trust SQL-supplied credentials.
Native already has a Parquet DWIO reader, but does not yet have this file
connector or a COPY-specific read authority.

The target write must carry a source-file identity into the immutable write
intent and Iceberg snapshot marker. Use a durable claim keyed by target table
UUID and canonical source path, with captured version/size/checksum for audit.
The first slice chooses path-only dedup: a later version at the same path is
still considered loaded, matching Databricks' documented rule. The claim is
fenced before Native work; a successful Iceberg commit publishes the same
identity in its snapshot summary; a post-commit journal transition records it
as complete. On lost commit response or coordinator restart, inspect the
target's committed marker and complete the claim before any retry. Keep the
marker reachable until reconciliation has durably completed; an expired
snapshot must never be interpreted as proof that no commit happened. A
concurrent claimant waits or fails closed until the first claim is resolved.
The existing query-ID commit fingerprint alone is insufficient for this.

Acceptance needs real MinIO with versioning and an actual Parquet object,
through SQL and JNI to Iceberg row values: first load, second-run zero new
rows, concurrent same-file COPY, source overwrite during staging, invalid
schema, denial outside external-location scope, worker failure before commit,
and ambiguous Iceberg commit with restart reconciliation. The existing
`SharedGovernedFileStorage` MinIO fixture offers real object-store plumbing,
but its current FILE callback configuration does not itself authorize COPY.

Before exposing URI COPY as successful, implement an authorized storage
location/profile resolution, a bounded file-list snapshot and deterministic
file identity, format-specific native scanning, and a durable identity/commit
record tied to the Iceberg table commit. Test real local or object-store
files, retries including ambiguous commit results, concurrent COPY writers,
file mutation/replacement, malformed records, and target rollback/no partial
commit. A URI syntax test or a fake S3 address is not end-to-end evidence.
