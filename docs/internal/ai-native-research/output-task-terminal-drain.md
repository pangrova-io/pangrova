# Actual result-task completion and retirement authority

The selected SDK requires PartitionedOutput consumption before task completion. Its `Task::setAllOutputConsumed` and `checkIfFinishedLocked` are the authority, rather than Java RUNNING result availability or the driver finishing its last input. [Pinned upstream Task.cpp](https://github.com/facebookincubator/velox/blob/3da0390118fa4b0addbfbdeb03f438ec1b1237a6/velox/exec/Task.cpp#L2182) documents this exact implementation. Pangrova `VeloxTaskRunner::waitForCompletion` uses the same completion future and explicitly describes the result task contract.

The real packaged-JNI failure first waited for FINISHED before issuing DoGet. Actual RUNNING with an unclaimed buffered result was correct. After the timeout, TaskManager interrupted its completion monitor, cancelled and joined Native, then tried publishing a released envelope from a still-RUNNING Java state. That second failure aborted fixture teardown and retained the process-wide Native fixture ownership guard. The guard detects the consequence correctly and is retained.

Shutdown now seals admission, interrupts monitors, requests actual cancellation, closes the actual transports, joins monitor exit, and invokes the existing real resource releaser. Only its validated release checkpoint is allowed to reconcile registry state. FINISHED follows RUNNING→FINISHING→FINISHED. An actual cancellation follows RUNNING/INITIALIZING→CANCELLING→CANCELLED. An existing committed FINISHED must match actual Native FINISHED. Existing FAILED/CANCELLED remains terminal; original terminal publication and its retained-envelope retries remain authoritative. A conflicting FINISHING/actual CANCELLED fails rather than bypassing commit. Explicit result retirement first requests cancellation through the existing registry owner; an already-committed completion retains its original finish.

`TaskRetirement` consumes the existing `executionDrainReceipt`, which validates exact attempt, Native authority, and NATIVE_OWNER_RELEASED, or the existing proven admission-closed-without-owner seal. It creates neither a release proof nor an inferred successful execution. The resource releaser still waits for Native physical release before returning Task memory and buffer grants. Failed cleanup retains the actual continuation; failed terminal delivery retains the original envelope. Global executor close remains forbidden until dependent owner cleanup has succeeded.
